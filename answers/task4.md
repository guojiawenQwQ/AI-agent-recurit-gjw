# Task 4：思考题

## 1. Make 和简单的 build.sh 有什么区别？

简单的 `build.sh` 通常按顺序执行一串 `gcc` 命令，每次都会把相关源文件全部重新编译，项目变大后既慢又难维护。

Make 根据 Makefile 中的依赖关系和文件修改时间做**增量构建**：只重新编译被改动的源文件，以及依赖它们的目标，从而节省时间。此外，Make 还支持伪目标（如 `clean`）、并行编译（如 `make -j`）等，更适合作为日常构建工具。

## 2. CMake 是编译器吗？

执行 `cmake --build build` 时，最终是谁在编译 C 源文件？

CMake **不是**编译器，而是**构建系统生成工具**。它根据 `CMakeLists.txt` 生成底层构建文件（在 Linux 上常见为 Makefile），再由这些构建文件去调用真正的编译器。

因此执行 `cmake --build build` 时，最终编译 C 源文件的是底层工具链中的编译器（如 `gcc` / `clang`），而不是 CMake 本身。

## 3. 为什么不希望每次都重新编译所有 `.c` 文件？

项目源文件很多时，全量重编耗时长、效率低。未修改的源文件再次编译，得到的 `.o` 通常与原来相同，属于重复劳动。合理做法是只重编变更部分及其依赖，其余目标文件直接复用，这正是 Make / CMake 增量构建的价值所在。
